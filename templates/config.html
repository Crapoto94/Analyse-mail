Configuration Microsoft Graph API

Permet de récupérer directement les connexions, le journal d'audit et les règles de messagerie d'une boîte via l'API Microsoft Graph, en alternative à l'import manuel de CSV.

Paramétrage requis côté Azure (une seule fois) :
  1. Dans le portail Azure → Microsoft Entra ID → Inscriptions d'applications → Nouvelle inscription.
  2. Notez l'ID d'application (client) et l'ID de l'annuaire (locataire).
  3. Dans Certificats et secrets, créez un nouveau secret client et copiez sa valeur (visible une seule fois).
  4. Dans Autorisations API → Ajouter une autorisation → Microsoft Graph → Autorisations d'application (pas déléguées), ajoutez :
    • AuditLog.Read.All — connexions (sign-ins) et journal d'audit
    • MailboxSettings.Read — règles de messagerie (transfert, suppression...)
    • Mail.Read — messages envoyés (optionnel, seulement si vous cochez "+ messages envoyés")
    • User.Read.All — résolution des utilisateurs, découverte automatique par motif (ex: adm-*) et scan des règles de messagerie de tout le tenant sur la page Surveillance. Combinée à AuditLog.Read.All, nécessaire aussi pour afficher la dernière connexion sur la fiche "Premiers secours" — s'il manque l'une des deux, Microsoft Graph renvoie une erreur 400 (pas 403) sur ce champ précis ; l'appli se rabat alors automatiquement sur le reste des informations du compte.
    • User.ReadWrite.All — actions d'urgence du menu Premiers secours (désactivation de compte, révocation des sessions, réinitialisation du mot de passe)
    • UserAuthenticationMethod.Read.All — consultation des méthodes MFA enregistrées sur la fiche "Premiers secours" (optionnel)
    • UserAuthenticationMethod.ReadWrite.All — action "Forcer le MFA (legacy)" sur la fiche "Premiers secours" (optionnel, sans effet si le MFA est géré par l'Accès conditionnel)
    • Policy.Read.All — affiche, sur la fiche "Premiers secours", comment le MFA est géré pour le compte (Défauts de sécurité activés ou non, politiques d'Accès conditionnel actives exigeant le MFA) — optionnel, sans cette permission ces deux lignes affichent "Inconnu"
  5. Cliquez sur Accorder un consentement admin pour le locataire (indispensable — sans ça les appels échouent en 403).
En plus, pour activer "Se connecter avec Microsoft" (page de connexion) :
  1. Sur la même inscription d'application, dans Authentification → Ajouter une plateforme → Web, ajoutez cette URI de redirection (celle réellement utilisée, ci-dessous) :
    {% if public_base_url %} Calculée depuis l'URL publique renseignée ci-dessous (indépendante du reverse proxy). {% else %} (doit être en HTTPS en production ; http://localhost fonctionne en développement — cette valeur reflète la façon dont cette requête a atteint l'application via le reverse proxy, donc rechargez cette page en passant par votre URL de prod pour voir la bonne valeur) {% endif %}
  2. Si l'application est derrière un reverse proxy (nginx, IIS...) qui termine le HTTPS, celui-ci doit transmettre l'en-tête X-Forwarded-Proto: https (et idéalement X-Forwarded-Host) — sinon l'URI générée reste en http:// et Azure refuse la connexion (AADSTS50011). Exemple nginx : 
    proxy_set_header X-Forwarded-Proto $scheme;
proxy_set_header X-Forwarded-Host $host;
    Si malgré une configuration correcte du proxy l'en-tête n'arrive toujours pas jusqu'à l'application (diagnostic possible sur /api/diag/proxy-headers), renseignez le champ "URL publique de l'application" ci-dessous : l'URI de redirection sera alors calculée directement depuis cette valeur, sans dépendre du proxy.
  3. Toujours dans Autorisations API, ajoutez cette fois des autorisations déléguées Microsoft Graph : openid, profile, email, User.Read (généralement sans consentement admin requis).
  4. Les comptes se connectant pour la première fois via Microsoft sont créés automatiquement : rôle administrateur si leur identifiant commence par adm-, utilisateur sinon.

Analyse IA

Permet d'utiliser un bouton « Analyse IA » sur chaque boîte pour demander à un modèle de langage d'expliquer le scénario le plus probable à partir des connexions et du journal d'audit déjà collectés, avec des recommandations. Trois fournisseurs compatibles, tous facultatifs : Groq, NVIDIA et Ollama (local). Chacun peut avoir plusieurs modèles enregistrés, avec le nom de votre choix — ils apparaissent tous dans le menu déroulant de /boite/x, avec l'étoile () sur le modèle par défaut. En cas d'échec du modèle choisi, les autres fournisseurs configurés sont essayés automatiquement en repli.

Alertes Microsoft Teams

Quand une boîte surveillée (page Surveillance) obtient lors d'un scan un score de risque strictement supérieur à {{ teams_alert_score_threshold }}/10 : une fiche d'incident est créée automatiquement pour cette boîte, l'import complet Microsoft Graph est lancé (connexions, journal d'audit, règles de messagerie et messages envoyés), puis l'analyse IA (si un fournisseur est configuré ci-dessous) — et enfin une alerte est postée dans le canal Teams configuré, avec le nom de la boîte, les éléments de suspicion de compromission détectés, et le lien direct vers la fiche déjà instruite. Réputation des IPs

Chaque adresse IP affichée dans l'application (connexions, messages, journal d'audit...) est accompagnée d'une pastille de réputation verte / orange / rouge, cliquable pour voir le détail (score d'abus, type d'usage — résidentiel, hébergeur/datacenter, mobile... — FAI, signalements...). Seuils appliqués au score d'abus AbuseIPDB (0-100) : rouge à partir de 75% (forte confiance d'abus), orange entre 25% et 74% (au moins un signalement, à vérifier), vert en dessous de 25%. Une IP identifiée comme hébergeur/datacenter ou VPN/proxy/Tor remonte au moins à l'orange même sans signalement — le type d'infrastructure est déjà un signal en contexte d'investigation.
Ces données viennent de AbuseIPDB (clé gratuite sur abuseipdb.com/account/api, 1000 requêtes/jour — chaque IP est mise en cache 4h dans la base locale avant tout nouvel appel, pour ne pas dépasser ce quota). Sans clé configurée, une estimation grossière est utilisée à la place (détection heuristique VPN/proxy/Tor + mots-clés hébergeur/cloud déjà utilisée ailleurs dans l'application) — nettement moins fiable, mais un affichage reste toujours proposé.
